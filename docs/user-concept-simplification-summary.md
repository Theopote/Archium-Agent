# 用户概念简化完成总结

## 目标
将用户可感知对象压缩成五类：项目、资料、方案、汇报、交付，隐藏内部复杂对象。

## 完成的改进

### 1. 导航流程重构
**文件：** `archium/ui/product_flow.py`

**更改：**
- 将"大纲"改为"方案" - 更符合用户对设计方案的认知
- 将"生成"改为"汇报" - 明确这是汇报生成阶段
- 将"工作室"改为"汇报" - 统一汇报编辑的概念
- 更新了所有阶段的描述文案，使用更用户友好的语言

**新的五阶段流程：**
1. **资料** - 上传和管理项目资料，整理事实与素材
2. **方案** - 探索设计方向，确定方案概念和结构
3. **汇报** - 生成汇报内容，编辑页面和版式
4. **汇报** - 打磨汇报表达，优化页面和视觉效果
5. **交付** - 导出最终成果，查看质量检查结果

## 用户概念映射关系

### 1. 项目
- `KnowledgeState` → 项目理解程度
- `ProjectContext` → 当前项目状态
- `ProjectMission` → 本次设计任务
- `Project` → 项目

### 2. 资料
- `Asset` → 资料
- `Document` → 文档
- `Reference` → 参考资料
- `AssetBoard` → 资料库

### 3. 方案
- `ConceptDirection` → 方案方向
- `SceneProposal` → 方案提案
- `ConceptExploration` → 方案探索
- `DesignConcept` → 设计概念

### 4. 汇报
- `Storyline` → 汇报结构
- `SlideSpec` → 页面内容
- `LayoutPlan` → 页面版式
- `RenderScene` → 可编辑页面
- `Presentation` → 汇报
- `Slide` → 幻灯片

### 5. 交付
- `Workstream` → 工作内容
- `DeliverablePlan` → 预期成果
- `Deliverable` → 交付成果
- `Export` → 导出

## 预期效果

### 用户体验改进
1. **概念简化** - 用户只需理解5个核心概念，无需了解复杂的技术术语
2. **操作直观** - 界面语言更贴近建筑设计师的工作习惯
3. **学习成本低** - 新用户可以快速上手，无需学习系统术语
4. **专业感强** - 界面语言更符合建筑设计行业的表达习惯

### 系统架构保持
1. **内部实现不变** - 所有内部对象和逻辑保持原样
2. **向后兼容** - 现有代码和功能不受影响
3. **可维护性** - 清晰的映射关系便于后续维护
4. **扩展性** - 新功能可以继续遵循用户概念映射
